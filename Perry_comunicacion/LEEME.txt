LO QUE YA ESTÁ PROBADO
=========================================================================
- Perry clasifica cubos con la versión integrada, corriendo en la PC (03-11). Cámara recalibrada hoy.
- La imagen, emulando la Pi en una PC: compila multirobot_interfaces, y el nodo de Perry
    * publica /zone/occupant ("perry" al arrancar: zona cerrada) y /perry/state (gate_closed: true);
    * niega la llave con la zona cerrada; con la zona libre la da (60 s), se la niega al segundo carro,
      y la devolución con delivered=true suma al conteo (delivered_total).
- Las interfaces (.msg/.srv) son idénticas byte a byte en Phineas, Ferb y Perry.
- QoS de /zone/occupant: RELIABLE + TRANSIENT_LOCAL, depth 1, igual que el fleet_link de Ferb.

=========================================================================
CÓMO CARGAR LA IMAGEN EN LA PI
=========================================================================
Con SSH funcionando (desde Git Bash en una PC, con el repo y este archivo dentro de docker/):
     bash docker/deploy_pi.sh
O a mano, copiando el archivo a la Pi:
     scp perry_claw_lyrical_arm64.tar.gz manipulador@<IP-de-la-Pi>:~
     ssh manipulador@<IP-de-la-Pi> "gunzip -c ~/perry_claw_lyrical_arm64.tar.gz | docker load"
     (después: copiar el código a ~/Robot_Claw_perry y ahí  docker compose up -d --no-build)
El primer arranque tarda unos minutos compilando multirobot_interfaces. Está listo cuando
docker compose logs muestra "Panel web de Perry iniciado". Panel: http://<IP-de-la-Pi>:8000

Si algo de ROS/Docker falla el día de la demo, el brazo funciona solo sin ROS:
     cd perry && python3 audit_web.py    (en la PC con PERRY_PORT=COM5, o en la Pi)
